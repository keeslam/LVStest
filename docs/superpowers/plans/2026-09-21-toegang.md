# Access on Staff Screens (B-27, B-28, B-29) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A typed address without rights shows a clear no-access page; one shared table decides which permission opens which screen; parts of a screen only ask for data the user may see; controls a user may not use stay visible but disabled with the reason.

**Architecture:** `shared/page-access.ts` is the single source for screen → permission, consumed by the sidebar, the route guard and the E2E registry. `ProtectedRoute` renders `NoAccessPage` instead of mounting the page. A small `RequiresPermission` wrapper disables controls and explains why. Cross-family queries are gated with the existing `useHasPermission` hook. The server stays as strict as it is.

**Tech Stack:** React 18, wouter, TanStack Query, shadcn/ui (Button, Tooltip, DropdownMenu), i18next, vitest (client jsdom, server with database), Playwright (`e2e/`).

**Spec:** `docs/superpowers/specs/2026-09-21-toegang-design.md` — binding; read it first. **Facts:** `docs/superpowers/specs/2026-09-21-toegang-feiten.md` — every page's queries with their server guards (section 2) and the 68 controls (section 3); the tables there are the work lists of Tasks 4 and 5. Verify a fact against the code before relying on it; line numbers drift.

## Global Constraints

- Nobody may read or do more than today. No server guard is widened or narrowed, except the single case the spec's §5 describes (a maintenance action route reachable only from the maintenance screen additionally accepts `manage_maintenance`), which must be reported.
- Every gate uses exactly the permissions the server route accepts; role `admin` always passes (the hooks already do this).
- The menu keeps HIDING screens a user may not open. Controls that are admin-only today stay hidden for non-admins. Controls whose dialog only reads data the user may already see are not disabled.
- No screen may show an error toast, the error boundary or an endless spinner for any combination of rights.
- User-visible text only through i18next, in `client/src/locales/nl` AND `en`; names of rights reuse the labels of the users dialog.
- E2E: `retries: 0`; never loosen the page-health guard (`e2e/support/guards.ts`); no allowlist entry without a written reason; the harness touches only database `lvs_e2e`. The desk story (`e2e/layer-b/desk/`) stays green with unchanged budgets.
- Server tests only with `DATABASE_URL=postgresql://postgres:postgres@localhost:5432/lvs_fixtest DATABASE_SSL=false`.
- Code and comments in English, matching the surrounding style. Commit messages: Dutch Conventional Commits, scope `(rechten)` for application code and `(e2e)` for tests under `e2e/`, written with a bash heredoc (`git commit -F - -- <paths> <<'EOF'`), ending with `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`. `git add` explicit paths only; never `schema-columns.json`, `.claude/launch.json`. Never push.
- One Playwright run at a time: port 5010 and database `lvs_e2e` are shared.
